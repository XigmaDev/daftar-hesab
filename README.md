# دفتر تراکنش — PWA آفلاین مدیریت تراکنش‌های بانکی

یک Progressive Web App کاملاً آفلاین برای دریافت، استخراج و مدیریت تراکنش‌های بانکی
از روی پیامک، با رابط کاربری کاملاً فارسی (RTL) و طراحی الهام‌گرفته از Material Design 3.

**تمام داده‌ها فقط داخل مرورگر/گوشی (IndexedDB) ذخیره می‌شوند. هیچ API یا سرور بیرونی
در این پروژه وجود ندارد و هیچ درخواست شبکه‌ای برای داده‌های کاربر ارسال نمی‌شود.**

---

## ۱. اجرای سریع (تست در مرورگر / نصب PWA)

چون PWA باید از طریق HTTP سرو شود (نه باز کردن مستقیم فایل)، یک سرور ساده محلی راه بیندازید:

```bash
cd persian-bank-pwa
python3 -m http.server 8080
# یا
npx serve .
```

سپس در گوشی اندروید، آدرس `http://<آی‌پی‌کامپیوتر>:8080` را در Chrome باز کنید و از منوی
سه‌نقطه گزینه‌ی «افزودن به صفحه اصلی / نصب برنامه» را انتخاب کنید. برنامه به‌صورت کامل
آفلاین نصب و اجرا می‌شود (Service Worker تمام فایل‌های لازم را از پیش کش می‌کند).

برای دیپلوی واقعی، کافی است همین پوشه را روی هر هاست استاتیک (GitHub Pages، Netlify،
یا حتی یک وب‌سرور محلی روی خود گوشی) قرار دهید — هیچ Backend لازم نیست.

## ۲. نکته‌ی مهم درباره‌ی دریافت خودکار پیامک

مرورگرها (و در نتیجه یک PWA خالص) به دلایل امنیتی اجازه‌ی دسترسی به پیامک‌های دریافتی
گوشی را نمی‌دهند. برای همین در این نسخه:

- صفحه‌ی **«افزودن تراکنش»** یک حالت **«استخراج از متن پیامک»** دارد: متن پیامک را
  پیست می‌کنید و موتور Regex (`js/smsParser.js`) اطلاعات را استخراج می‌کند — دقیقاً
  همان منطقی که در دریافت خودکار هم استفاده خواهد شد.
- برای **دریافت کاملاً خودکار** پیامک (بدون دخالت کاربر)، باید این PWA با **Capacitor**
  به یک اپ بومی اندروید بسته‌بندی شود. تمام فایل‌های لازم برای این کار آماده است:
  - `capacitor.config.json` و `package.json`
  - `android-native-sample/SmsReceiverPlugin.kt` — افزونه‌ی بومی نمونه که با
    `BroadcastReceiver` به پیامک گوش می‌دهد و آن را به `js/app.js` می‌فرستد
    (رویداد `smsReceived`، که `App.js` از پیش برای شنیدنش آماده است).
  - `android-native-sample/AndroidManifest-additions.xml` — مجوزهای
    `RECEIVE_SMS` / `READ_SMS` که باید اضافه شوند.

  مراحل بسته‌بندی:
  ```bash
  npm install
  npx cap add android
  # فایل SmsReceiverPlugin.kt را به android/app/src/main/java/ir/local/daftartarakonesh/ کپی کنید
  # مجوزهای AndroidManifest-additions.xml را به AndroidManifest.xml اضافه کنید
  # registerPlugin(SmsReceiverPlugin.class) را در MainActivity اضافه کنید
  npx cap sync android
  npx cap open android   # ساخت APK/AAB نهایی در Android Studio
  ```
  این مرحله نیازمند Android Studio و ساخت روی دستگاه واقعی/شبیه‌ساز است و در این محیط
  قابل Build و تست خودکار نبود؛ کد به‌صورت مرجع کامل و مستند ارائه شده است.

## ۳. ساختار پروژه

```
persian-bank-pwa/
├── index.html                 صفحه اصلی، اسپلش، درخواست مجوز اولیه، قفل PIN
├── manifest.json               Web App Manifest (نصب PWA)
├── sw.js                       Service Worker (کش کامل برای اجرای آفلاین)
├── package.json / capacitor.config.json   بسته‌بندی اختیاری برای اندروید
├── css/
│   └── style.css               سیستم طراحی (رنگ، تایپوگرافی، کامپوننت‌ها، تم تیره/روشن)
├── js/
│   ├── db.js                   لایه دیتابیس (IndexedDB) — Repository Pattern
│   ├── smsParser.js            تشخیص بانک + استخراج اطلاعات با Regex
│   ├── charts.js                نمودار خطی و دایره‌ای با SVG خام (بدون کتابخانه)
│   ├── seed.js                  داده نمونه برای تست اولیه
│   └── app.js                   Router + رندر تمام صفحات + منطق برنامه
├── icons/                      آیکون‌های PWA (192، 512، maskable)
└── android-native-sample/      کد مرجع افزونه بومی دریافت پیامک (Capacitor/Kotlin)
```

## ۴. طراحی دیتابیس (IndexedDB)

| Store          | فیلدهای کلیدی                                                                 | ایندکس‌ها |
|-----------------|-------------------------------------------------------------------------------|-----------|
| `transactions`  | bankName, type, amount, balanceAfter, cardNumber, accountNumber, trackingCode, accountId, date, time, rawText, status, unitId, categoryId, description, tags[], createdAt | status, date, bank, account, unit, category, type, amount, trackingCode |
| `banks`         | name, color                                                                    | name (unique) |
| `accounts`      | bankId, title, accountType, cardNumber, accountNumber, iban, initialBalance   | bank, card, accountNumber |
| `units`         | name, color                                                                    | name (unique) |
| `categories`    | name, unitId, color                                                           | name, unit |
| `tags`          | name                                                                           | name (unique) |
| `settings`      | key → value (تک‌رکوردی: theme, pin, smsEnabled, notifEnabled, onboarded)      | keyPath: key |
| `backups`       | createdAt (ابرداده‌ی فایل‌های پشتیبان تهیه‌شده)                              | date |

روابط: هر `transaction` به‌صورت اختیاری به یک `unit`، یک `category` و یک `account`
متصل می‌شود (Foreign Key منطقی، بدون Constraint سخت‌گیرانه تا حذف واحد/دسته/حساب باعث
از دست رفتن تراکنش نشود). هر `account` به یک `bank` متصل است. **موجودی فعلی هر حساب
ذخیره نمی‌شود، بلکه همیشه به‌صورت پویا از `initialBalance` + مجموع تراکنش‌های متصل به
همان `accountId` محاسبه می‌شود** — این یعنی هیچ‌وقت موجودی و تراکنش‌ها ناهم‌خوان
(Out of sync) نمی‌شوند.

## ۵. موتور تشخیص پیامک

`js/smsParser.js` شامل فهرست بانک‌های ایرانی (ملت، ملی، صادرات، تجارت، سپه، بلو، سامان،
پاسارگاد، آینده، پارسیان، شهر، کشاورزی، رفاه، اقتصاد نوین، سینا، دی، کارآفرین، رسالت،
مهر ایران، ایران زمین، گردشگری، مسکن، پست بانک، انصار، حکمت ایرانیان و ...) به همراه
الگوهای Regex چندلایه برای مبلغ، مانده، شماره کارت/حساب، کد پیگیری، تاریخ و ساعت است.

چون فرمت پیامک بین بانک‌ها — و حتی بین نسخه‌های مختلف سامانه‌ی پیامکی یک بانک — کاملاً
متفاوت است (مثلاً بعضی بانک‌ها به‌جای «مبلغ: ۱۰۰۰۰۰ ریال» می‌نویسند «برداشت:۱۰۰۰۰۰» یا حتی
فقط «۱۰۰۰۰۰-» بدون هیچ کلیدواژه‌ای)، این موتور برای هر فیلد چند الگوی جایگزین را به ترتیب
اولویت امتحان می‌کند:

- **مبلغ**: ابتدا الگوی «مبلغ: عدد»، سپس «برداشت:عدد/واریز:عدد»، سپس عدد همراه «ریال/تومان»
  در هر جای متن، و در نهایت عدد به‌تنهایی که بلافاصله علامت `+`/`-` دارد.
- **نوع تراکنش**: از کلمات کلیدی («برداشت»، «واریز»، «خرید»، «پرید» و...)، و اگر هیچ‌کدام
  نبود، از علامت `+`/`-` چسبیده به مبلغ حدس زده می‌شود.
- **تاریخ**: چند فرمت را پشتیبانی می‌کند — کامل با جداکننده‌ی `/`، `-` یا `.` (شامل ارقام
  فارسی مثل «۱۴۰۵.۰۴.۲۴»)، کوتاه بدون سال («۱/۴»)، و فشرده بدون جداکننده بلافاصله قبل از
  ساعت («۱۱۲۸-۲۳:۵۸»). برای جلوگیری از قاطی‌شدن با شماره‌حساب‌های خط‌تیره‌دار، اولویت با
  الگویی است که به سال شمسی (۱۳xx/۱۴xx) شبیه‌تر باشد.
- **حروف عربی**: چون بعضی سامانه‌های بانکی از حروف عربی «ي» و «ك» به‌جای فارسی «ی» و «ک»
  استفاده می‌کنند (مثلاً «بانک ملي» یا «بانك صادرات»)، متن قبل از تشخیص یکسان‌سازی می‌شود.

اگر مبلغ یا بانک همچنان تشخیص داده نشود، فیلد `recognized: false` برمی‌گردد و کاربر
می‌تواند در فرم افزودن تراکنش، مقادیر را دستی تکمیل کند. برای پشتیبانی از فرمت‌های خاص و
جدید، کافی است الگوی Regex مربوطه در همین فایل گسترش داده شود.

## ۶. دسته‌بندی سریع در کارتابل

برای اینکه بررسی تراکنش‌های تازه از پیامک تا حد امکان سریع باشد، با ضربه روی هر تراکنش
در **کارتابل**، به‌جای باز شدن فرم کامل، یک شیت کوچک باز می‌شود که در آن:

- واحد و دسته‌بندی به‌صورت چیپ‌های قابل لمس (تک‌انتخابی) نمایش داده می‌شوند — یک ضربه کافی است.
- اگر واحد/دسته‌بندی مدنظر هنوز وجود ندارد، با دکمه‌ی «+ جدید» می‌توان همان‌جا و بدون خروج
  از شیت، آن را ساخت و بلافاصله انتخاب کرد.
- با دکمه‌ی «ثبت و انتقال به تراکنش‌ها»، تراکنش دسته‌بندی شده، وضعیتش «بررسی‌شده» می‌شود و
  از کارتابل خارج می‌شود.
- دکمه‌ی «ویرایش کامل تراکنش» هم برای زمانی است که نیاز به اصلاح مبلغ، توضیحات یا سایر
  جزئیات باشد.

فشار طولانی (Long Press) روی هر تراکنش هم مثل قبل حالت انتخاب چندتایی را برای حذف/ویرایش
گروهی فعال می‌کند.

## ۷. امکانات پیاده‌شده

- **مدیریت بانک‌ها و حساب‌ها** (تنظیمات ← بانک‌ها و حساب‌ها): افزودن هر تعداد بانک
  (از فهرست بانک‌های ایرانی یا نام دلخواه)، به‌همراه رنگ اختصاصی؛ برای هر بانک می‌توان
  چند حساب/کارت با عنوان، نوع حساب (جاری/پس‌انداز/کارت/ارزی)، شماره کارت، شماره حساب،
  شماره شبا و **موجودی اولیه** ثبت کرد. موجودی فعلی هر حساب به‌صورت خودکار از
  «موجودی اولیه + مجموع تراکنش‌های متصل به همان حساب» محاسبه می‌شود.
- داشبورد با موجودی، جمع واریز/برداشت به تفکیک بازه (امروز/هفته/ماه/سال/کل)، بخش
  «موجودی هر حساب» (در صورت ثبت بانک/حساب)، نمودار روند ۷ روز اخیر، نمودار دایره‌ای
  دسته‌بندی، تراکنش‌های اخیر.
- کارتابل تراکنش‌های جدید با وضعیت «جدید» تا زمان بررسی کاربر.
- لیست تراکنش‌ها با جستجوی پیشرفته (متن پیامک، مبلغ، شماره کارت/حساب، توضیحات) و فیلتر
  بر اساس وضعیت/واحد/دسته‌بندی.
- انتخاب چندتایی با فشار طولانی (Long Press) + حذف گروهی + ویرایش گروهی.
- صفحه جزئیات تراکنش با متن کامل پیامک، تمام فیلدهای استخراج‌شده، حساب متصل، حذف تکی.
- افزودن/ویرایش تراکنش (دستی یا با پیست پیامک) با امکان اتصال به یک حساب مشخص؛ هنگام
  استخراج از پیامک، در صورت تطابق شماره کارت/حساب با یکی از حساب‌های ثبت‌شده، حساب
  به‌صورت خودکار پیشنهاد می‌شود.
- مدیریت واحدها و دسته‌بندی‌ها (ایجاد/ویرایش/حذف/رنگ اختصاصی).
- گزارش‌ساز با فیلتر ترکیبی و خروجی CSV، JSON و چاپ/PDF (از طریق چاپ مرورگر).
- تنظیمات: تم روشن/تیره، رمز عبور ۴ رقمی (PIN)، فعال/غیرفعال‌سازی دریافت پیامک و اعلان.
- پشتیبان‌گیری کامل (Export/Import JSON — شامل بانک‌ها و حساب‌ها) و پاک‌سازی کل داده‌ها.
- نصب PWA + اجرای کاملاً آفلاین با Service Worker.

## ۸. محدودیت‌های شناخته‌شده / گام‌های بعدی

- دریافت *خودکار* پیامک فقط در بسته‌ی Capacitor فعال می‌شود (بخش ۲).
- ورود با اثر انگشت (WebAuthn) در این نسخه پیاده نشده؛ قفل PIN جایگزین آن است. برای
  افزودن اثر انگشت واقعی در اپ بسته‌بندی‌شده، از افزونه‌ی `@capacitor/biometric-auth`
  می‌توان استفاده کرد.
- تاریخ‌های شمسی به‌صورت متن خام (همانی که در پیامک آمده) ذخیره می‌شوند؛ برای محاسبات
  دقیق «این هفته/این ماه شمسی» می‌توان یک کتابخانه‌ی تقویم جلالی افلاین اضافه کرد.
- الگوهای Regex برای فرمت‌های خاص و نادر پیامک ممکن است نیاز به تنظیم دقیق‌تر داشته
  باشند؛ ساختار کد برای افزودن الگوی جدید بسیار ساده است (`js/smsParser.js`).
